## Рабочий стол QA

- `dist/concept.html` — новый первый интерфейс для того же Дня 1, доступный со стартового экрана.
- Этап охватывает задачу SP-214, требования, чек-лист, справочник промокодов и расчёт корзины.
- После этапа имя, решения и баллы переходят в карточный сценарий на проверку оформления заказа.
- Инструменты показывают подготовленные учебные данные; они не подключены к настоящим сервисам.
- Закрытая тестовая копия обновлена до версии 2 после успешного GitHub Actions №37; источник Site: `4c2a8214ccf4a134ba1a7607dacb46406b1447cc`. Публичный Site отдельно обновлён до версии 8, источник Site: `e828091bb6ea377301966d0d30e2a1f38da2d810`. Перед публикацией сравнен весь настроенный каталог `dist`; содержимое сайтов одинаково. Проекты Sites остаются отдельными, GitHub push их автоматически не обновляет.
- Тесты проверяют мобильную ширину 390 px, но это не заменяет ручную проверку на реальном Android. iOS пока не проверен.
- По сообщению пользователя, после отметки всех четырёх пунктов показывалось «Чек-лист готов», но кнопка не реагировала в Android. Исправление: кнопка всегда семантически доступна, готовность отмечается стилем, обработчик охраняет переход и сообщает, если пунктов не хватает. Ранний E2E-вариант с `aria-disabled` CI отклонил как недоступный для взаимодействия. Полные E2E успешны в GitHub Actions №37 и №39; версия 2 опубликована в приватной копии и версия 8 — в публичном Site. Ручная проверка на Android ожидается.
- Критерии оценки зафиксированы в `docs/DESIGN_CONCEPT_WORKSPACE.md`.

## Последние исправления и решения

- SQL-упражнение обозначает диалект MS SQL Server и принимает смыслово эквивалентные ограниченные запросы с разным регистром, порядком полей и лимитом до 10 строк.
- Упражнение отклоняет `SELECT *`, лишние команды, неподходящую таблицу или фильтр и отсутствие обязательных полей `id`, `user_id`, `order_date`.
- Схема учебной таблицы в базе знаний приведена в соответствие с интерфейсом: `id`, `user_id`, `total`, `status`, `order_date`.
- Прогресс нового рабочего стола хранится локально отдельно до перехода к основному маршруту; если существовала другая сохранённая смена, она архивируется в этом браузере.
- Передача из рабочего стола направляет пользователя на подготовку исследования DevTools/Network (этап 11), прежде чем он повторит оформление заказа.

## Исправления после ручного прохождения

- Чек-лист требований использует настоящие checkbox-контролы и не позволяет продолжить без трёх отметок.
- Баг-репорт проверяется не только по длине: заголовок, фактический и ожидаемый результаты должны содержать ключевые факты сценария.
- E2E отдельно проверяет отклонение бессмысленного набора символов.

## Неизменные ограничения

- Статическое приложение без аккаунтов и зависимости от ChatGPT.
- Имя и прогресс хранятся только локально в браузере пользователя.
- Интерфейс работает на телефоне и ноутбуке.
- Каждое изменение проходит автоматические проверки, commit, push и проверку публикации. Для браузерных E2E нужен Chromium; если среда не может его скачать, такой прогон помечается непроверенным, а не успешным.
- В рабочей среде Codex Chromium отсутствовал; локальная загрузка Playwright вернула пустой/повреждённый ZIP. GitHub Actions самостоятельно установил Chromium и прошёл полный E2E (№39).
