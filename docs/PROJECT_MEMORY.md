# Банк памяти проекта «Первый день QA»

Этот файл — короткая точка входа в проект. Перед любым новым этапом его нужно прочитать вместе с `AGENTS.md` и `docs/DEVELOPMENT_PROCESS.md`. После важного решения или релиза файл нужно обновить.

## Зачем существует продукт

«Первый день QA» — мобильное учебное веб-приложение для новичков без опыта. Пользователь проходит короткую симуляцию рабочего дня ручного тестировщика в команде учебного интернет-магазина: выбирает действия, видит последствия и знакомится с DevTools, API, SQL, Jira и документацией.

## Текущее состояние

- Версия: первый публичный прототип.
- Приложение: https://pervyi-den-qa.staverviktor17.chatgpt.site
- Исходный код: https://github.com/viktor-qatester/qa-first-day
- Формат: статическое мобильное веб-приложение без регистрации и сервера.
- Хранение прогресса: локально в браузере через `localStorage`.
- Основной сценарий: ввод имени → карточки рабочего дня → выборы и последствия → DevTools/Network → API → SQL → баг-репорт → итог.
- Автоматическая проверка: `npm test`.

## Уже принятые решения

- Рабочее название оставить «Первый день QA» до появления причины его менять.
- Сначала проверить один законченный E2E-сценарий, затем расширять приложение.
- На старте пользователь вводит имя; персонажи обращаются к нему по имени.
- Выбор делается нажатием на всю карточку ответа. Элемент выбора не должен перекрывать текст.
- У каждого существенного выбора должна быть понятная реакция и учебное объяснение последствий.
- Изображения использовать выборочно: персонажи, состояние продукта и доказательства бага, а не как украшение каждой карточки.
- Приложение публичное, работает по обычной ссылке и не требует аккаунта ChatGPT.
- GitHub — основное место хранения исходного кода. После проверки релиз публикуется на действующий адрес приложения.

## Границы текущего прототипа

- Jira, API, SQL и DevTools сейчас имитируются внутри сценария; реальных внешних систем и базы данных нет.
- Есть только один учебный рабочий день и ограниченное ветвление.
- Результат и оценка предназначены для обучения, а не для найма или аттестации.
- Автотесты пока проверяют структуру и обязательные элементы, но не заменяют ручной E2E-проход на телефоне.

## Обязательный цикл каждого изменения

1. Зафиксировать проблему или идею и ожидаемый результат.
2. Описать критерии приёмки и затронутые экраны.
3. Проверить текущую публичную версию и воспроизвести исходное состояние.
4. Внести одно понятное изменение без побочных переделок.
5. Запустить `npm test`.
6. Вручную пройти затронутый путь, включая мобильную ширину, возврат назад и повторный запуск.
7. Проверить имя пользователя, выборы, последствия, прогресс и сохранение состояния.
8. Опубликовать только успешно проверенную версию.
9. Выполнить короткую проверку публичной ссылки и обновить этот банк памяти.

## Навыки и утилиты проекта

| Область | Для чего нужна |
|---|---|
| GitHub | задачи, история изменений, проверка и хранение исходного кода |
| Sites | публикация проверенной статической версии по общей ссылке |
| HTML/CSS/JavaScript | интерфейс, логика карточек и локальное сохранение |
| Node.js + `npm test` | автоматическая smoke-проверка структуры сценария |
| Ручное E2E-тестирование | проверка полного пользовательского пути и последствий выбора |
| Мобильная проверка | контроль читаемости, нажатий, переполнений и адаптивности |
| Генерация изображений | создание согласованных учебных иллюстраций при необходимости |

## Следующий этап

Владелец проекта и один приглашённый пользователь проходят сценарий на телефоне. Наблюдения фиксируются отдельно как: проблема, место в сценарии, ожидаемое поведение, фактическое поведение и важность. После этого выбирается только одно небольшое улучшение для следующего цикла.

## Что пока не добавляем

- регистрацию и аккаунты;
- настоящий сервер, базу данных или интеграцию с Jira;
- несколько больших сценариев одновременно;
- сложную аналитику прохождений;
- декоративные изображения без учебной функции.
