# Цикл разработки и тестирования

## 1 Идея

Фиксируем проблему пользователя и ожидаемую учебную ценность. Не начинаем с реализации интерфейса.

## 2 GitHub Issue

Каждый этап получает отдельную задачу с описанием:

- цель;
- пользовательский сценарий;
- критерии приёмки;
- риски;
- необходимые проверки.

## 3 Базовая проверка

До изменения подтверждаем, что стабильная версия:

- открывается по публичной ссылке;
- принимает имя;
- сохраняет прогресс;
- проходит от старта до результата;
- корректно работает на телефоне;
- не содержит ошибок JavaScript.

## 4 Разработка

Работа ведётся в отдельной ветке. Изменение должно быть небольшим и проверяемым.

## 5 Тестирование

Обязательные уровни:

1. Автоматический smoke-тест структуры приложения.
2. Ручной E2E основного пути.
3. Негативные и альтернативные решения.
4. Мобильная проверка на ширине 360 пикселей.
5. Ретест исправленного дефекта.
6. Короткая регрессия существующих функций.

## 6 Pull Request

В PR указываются:

- что изменено;
- зачем изменено;
- какие критерии выполнены;
- какие тесты проведены;
- известные ограничения;
- ссылка на опубликованную версию после выпуска.

## 7 Выпуск

После объединения публикуется новая версия. Затем повторяются старт, один основной сценарий, сохранение прогресса и итоговый экран.

## 8 Обратная связь

Замечания пользователей оформляются как дефекты или предложения. Следующий этап планируется только после их разбора.
