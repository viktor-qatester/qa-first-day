# Разбор отзывов: итерация 1

Дата фиксации: 28 сентября 2026 года.

## Приоритеты

### P0 — корректность обучения

- DevTools/Network открывается до воспроизведения действия.
- Скидка сверяется с требованиями и настройкой в справочнике.
- Поведение API оценивается по контракту Swagger/OpenAPI: HTTP 200 может содержать бизнес-ошибку.
- SQL-запрос ограничивает выборку, перечисляет поля и задаёт сортировку.
- Два запроса и два разных `order_id` называются двумя созданными заказами, а не дубликатами строк.
- Варианты ответа до выбора выглядят нейтрально и не подсказывают решение.

### P1 — реалистичность рабочего процесса

- Задача приходит как часть скоупа сборки, без искусственного «сегодня ты проверяешь».
- До проверки составляется короткий чек-лист; исследование можно вести параллельно с уточнением требований.
- У разработчика уточняются его шаги и условия воспроизведения.
- После исправления выполняются ретест и короткий риск-ориентированный регресс.
- Сценарий двойного нажатия проверяется на уровнях UI, Network, API и БД.

### P2 — следующие расширения

- Детальнее показать жизненный цикл заказа и переходы статусов.
- Добавить альтернативные причины похожего симптома.
- Расширить ветвления и последствия решений после проверки текущей версии пользователями.

## Критерий завершения итерации

Все пункты P0 и P1 отражены в сценарии, полный правильный маршрут автоматически проходит от ввода имени до результата, мобильная ширина не ломает элементы выбора, а публичная версия обновляется только после зелёных проверок.
