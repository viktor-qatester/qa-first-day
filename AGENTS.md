# Правила работы над проектом

## Главный принцип

Новый этап не начинается, пока текущая версия не прошла обязательные проверки.

## Перед изменением

1. Проверить `git status` и сохранить незавершённую работу.
2. Описать задачу и критерии приёмки.
3. Выполнить smoke-тест текущей стабильной версии.
4. Создать отдельную ветку для изменения.

## Во время изменения

- Не смешивать несколько крупных функций в одном изменении.
- Сохранять мобильную адаптацию и доступность.
- Не удалять работающую механику без согласованной причины.
- Добавлять или обновлять проверку для новой логики.

## Перед публикацией

1. Запустить `npm test`.
2. Пройти основной E2E-путь вручную.
3. Проверить негативную ветку хотя бы одного решения.
4. Проверить ввод имени, сохранение, сброс и итоговый балл.
5. Проверить ширину 360 пикселей и отсутствие наложений.
6. Оформить Pull Request с результатами тестирования.
7. После публикации выполнить production smoke.

## Запрещено

- пушить заведомо непроверенную версию в `main`;
- пропускать регрессию из-за небольшого размера изменения;
- менять формулы оценки без проверки максимального и минимального результата;
- использовать реальные персональные, платёжные или медицинские данные в сценариях.
